# 后端待处理事项

> 本文件登记**前端已按当前契约实现、但需要后端修正或确认**的开放事项。
> 维护方式：每条一个稳定编号；关闭后只保留编号与结论，编号不复用；新增条目必须写清“当前前端行为”与“期望后端行为”，避免同一条被重复讨论。
> 关联：[架构说明](../architecture.md)、[工程说明](../engineering.md)、功能规格目录 [specs/](../../specs/README.md)。

## 使用规则

1. 只登记跨团队、需要后端动作的事项；纯前端待办留在 `specs/NNN-slug/tasks.md`。
2. 编号规则：`B1`、`B2`…（Backend）；已被产品/后端关闭的条目继续占用编号。
3. 状态取值：`open`（等待后端）、`partial`（部分完成）、`closed`（结论已定，不再跟踪）。
4. 前端行为变化时同步更新“当前前端行为”，否则条目会过期。
5. 与后端对齐后必须给出结论（做了什么、为什么不做、替代方案），不能只删条目。

## 条目模板

```md
### B<n>. 一句话标题（状态：open | partial | closed）

- 状态：open（YYYY-MM-DD）
- 当前前端行为：前端现在如何降级/兼容，涉及哪个文件。
- 期望后端行为：接口、字段、错误码或配置需要怎么改。
- 影响：不解决时的用户可见后果。
- 结论（关闭时填写）：YYYY-MM-DD 做了什么 / 为什么不做。
```
